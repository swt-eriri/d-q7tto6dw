架构级：知道做什么、为什么即可。

密钥、日志监控、上线检查

机制：密钥与安全、可观测性（后端框架 0004 第 8、9 节）。例子：一把桥接服务密钥的一生；后台进程挂了，从哪些指标能看出来。

这一页想让你讲得出：每类密钥存在哪、谁能用；模块为什么不自己处理密钥；出问题时先看哪几个指标；没有追踪系统时怎么把两个进程的日志串起来；健康检查和就绪检查各看什么。 框架 = 你负责的 0004；DSH 适配层 = 0002。

① 先分清四对词

加密存储 ≠ 只存哈希

加密存储
以后还要拿回明文用的，加密后存库，比如桥接服务密钥（入口验签要用）、模型凭据。
只存哈希
只需要核对、不需要拿回的，只存 SHA-256，比如登录 cookie、进程令牌、应用凭据。库泄露了也拿不到能用的值。
先问「以后要不要用到明文」，再决定存哪种。

主密钥 ≠ 数据密钥

主密钥
部署环境变量注入（行内有密钥管理服务就接入），不进库。
数据密钥
真正加密数据的密钥，自己也被主密钥加密后和密文存在一起，带密钥版本号。
这叫信封加密（AES-256-GCM）。换主密钥时只要重新加密数据密钥，轮换手工进行。

健康检查 ≠ 就绪检查

/healthz
只看进程还活着。
/readyz
看数据库能连上、迁移版本对得上。
DSH 不可用不影响就绪：平台照常提供历史、管理功能，执行类操作返回 503。

请求 ID ≠ 追踪 ID

请求 ID
一次入口请求一个，出错时返回给用户，用来查这次请求。
追踪 ID
一件事从头到尾一个：请求、它引出的任务和事件都带同一个，跨进程也不变。
P0 不部署追踪系统，按追踪 ID 搜日志就能把请求进程和后台进程的日志串起来。

④ 出问题先看什么

现象先看的指标
页面慢、报错多HTTP 延迟与错误率；DSH 调用延迟与按分类的错误数
回答停住不动跟随器数量与事件滞后（A1、A10）
后台任务没人做任务队列长度与最老任务等待时间；死信任务数（A6）
事件该发生的没发生事件登记表的未完成数与最老未完成时长（超过 1 小时告警，A5）
Agent 调 tool 失败tool 回调核验失败数（按失败步骤，A8）
浏览器收不到推送事件流在线连接数（A9）

日志是 JSON，每条带请求 ID、追踪 ID、模块、主体 ID（不带姓名）。指标以 Prometheus 格式暴露，接入行内监控的方式由运维定。

⑤ 为什么这样做 每条都是「不这样会坏在哪」

1. 为什么模块不能自己处理密钥，只能调 secrets.encrypt / decrypt？

各模块自己加解密：每个模块各写一套，算法、密钥版本、轮换方式不一致，出了问题没法统一换。

集中在内核：算法和主密钥只在一个地方，换主密钥时只改这一处。

2. 为什么桥接服务密钥每个进程一把、重启就换？

它就放在 DSH 进程的环境变量里，泄露的可能性比放在平台内部大。一个进程一把，泄露只影响一个进程；重启就换，泄露的密钥寿命不超过这个进程。泄露后最坏能怎样，见 A8 ④ 第 4 条。

3. 为什么 DSH 不可用时平台仍算「就绪」？

算「不就绪」：负载均衡会把请求进程摘掉，用户连历史记录、管理页面都打不开，而这些本来不依赖 DSH。

所以就绪只看数据库和迁移版本；执行类操作单独返回 503 common.dependency-unavailable，DSH 的状态由运维模块的运行状态页展示。

4. 为什么日志里只带主体 ID、不带姓名，还要脱敏？

日志的查看范围比业务库宽得多。把姓名、cookie、签名、凭据写进日志，等于把敏感信息复制到了一个管得更松的地方。

请求头里的凭据、cookie、签名，事件正文里已知的敏感字段一律打码；DSH 返回的原始错误不直接进响应。

5. 为什么 P0 不部署追踪系统？

多一个要部署、要运维的组件。请求、任务、事件都带追踪 ID 并写进每条日志，按它搜日志就能串起请求进程和后台进程；tool 回调的日志带原执行的追踪 ID。行内有追踪平台时再接 OpenTelemetry。

⑥ 自测 先自己想，再点开

1. 张三说「我的回答一直不出来」，给了你一个请求 ID。你怎么查？

用请求 ID 在日志里找到这次请求，拿到它的追踪 ID；再用追踪 ID 搜，能看到后台进程里跟随任务、事件处理的日志。同时看跟随器滞后、任务队列最老等待这些指标，判断是不是后台进程的问题。

2. DSH 主机宕了，负载均衡会不会把请求进程摘掉？

不会。就绪检查只看数据库和迁移版本。用户还能看历史、做管理，执行类操作返回 503。

3. 登录 cookie 和桥接服务密钥，为什么一个只存哈希、一个加密存储？

cookie 只需要核对（算哈希比一比），不需要拿回明文；桥接服务密钥入口验签时要用明文重新算签名，所以只能加密存储。

出处：0004 第 8 节（密钥表、信封加密、日志脱敏、/internal/* 不对办公网转发）、第 9 节（日志、指标、追踪、健康检查）、第 3.3 节（1 小时告警）、第 4.4 节；0002 第 3.3 节（ensureProcess、密钥轮换）。
示意，不是 RFC 定的：时间、ID、指标的具体数值、告警阈值（除事件登记 1 小时外）。
