Agent 调业务 tool 时，平台怎么确认「这是谁的哪一次执行」

机制：tool 回调核验（后端框架 0004 第 4.4、8、10.1 节）。例子：张三的会话里，Agent 调「取数」tool。

这一页想让你讲得出：DSH 里的 Agent 调平台时为什么带不了令牌；平台靠什么认出「这是张三的这次执行」；核验三步各防什么；桥接插件重试为什么安全；密钥泄露最坏能怎样。 框架 = 你负责的 0004；M01 = 会话（嘉敏）；M03 = 取数；M07 = 身份（你的 0006）；DSH 侧 = 桥接插件（0002）。

① 先分清四对词② 走一遍（每一关都可以不通过）③ 两类特殊回调④ 为什么这样做⑤ 它不保证什么⑥ 自测

① 先分清四对词

签名 ≠ 身份

签名
证明「这个请求来自某个 DSH 进程上的桥接插件，内容没被改过」。每个 DSH 进程一把服务密钥。
身份
证明「这是张三的这一次执行」。不在请求里，是平台按 DSH 会话 ID 去会话模块查出来的执行凭据。
签名对了只说明「是自己人发的」，还不知道是替谁发的。

参数 ≠ 身份

参数
模型填的，比如「查上个月的存款余额」。只当作业务输入。
身份
参数里没有任何身份字段。模型就算写「替李四查」，平台也不看。
DSH 会话 ID、调用 ID 是 DSH 给的执行上下文，不是模型填的。

防重放 ≠ 幂等

防重放
回调记录表（保留 10 分钟）：同一个回调再来一次，返回上次的结果；内容不同，拒绝。挡的是「同一个请求被重复送达或被人重放」。
幂等
模块事务里的幂等记录（保留 24 小时）：保证业务写入只生效一次。
两者用同一个键：DSH 会话 ID + 调用 ID + 第几次回调。

tool 回调 ≠ MCP 调用

tool 回调
经桥接插件回调平台，按 DSH 会话查执行凭据，精确到这一次执行。本页讲的就是这个。
MCP 调用
DSH 进程直接发给平台的 MCP 代理，只能带进程环境变量里的令牌，精确到这个进程（B5 讲）。
取数、读知识、登记产出这些平台业务 tool 走回调；mem0、行内 MCP 服务走 MCP。
用到的三个基础概念（不熟就点开）

HMAC 签名：发送方用密钥对「方法 + 路径 + 时间戳 + 请求体摘要」算一个值附在请求上；接收方用同一把密钥再算一遍，对得上就说明请求来自持有密钥的人、内容没被改。密钥本身不在请求里传。

重放：把截获的旧请求原样再发一次。时间戳（±60 秒）加回调记录表，让旧请求要么过期、要么只能拿到上次的结果。

桥接插件：装在 DSH 里的一个插件。Agent 调平台的业务 tool 时，实际执行的是它：它把调用转成一个签了名的 HTTP 请求发给平台，再把平台的结果交回给 Agent。

③ 两类特殊回调

是什么和普通 tool 回调的区别
非 tool 回调
/internal/exec/v1		桥接插件每轮开始取剩余额度（get_limits）、登记预算暂停（report_budget_pause）没有对应的 tool 调用，也就没有调用 ID：插件为每个请求生成一个请求 ID 填在调用 ID 的位置、第几次回调填 1，防重放照常。第 2 步换成「按 DSH 会话找活动执行，并核对连接属于会话所在的进程」
发布探测进程
路由键 system:probe		M04 发布时跑的探测会话（A5 第 5 步「探测」）没有会话模块的执行，取不到额度。入口用第 1 步查到的路由键认出它，改向 M04 取一次性的探测执行：额度 1 次模型调用、0 次 tool 调用，没有取数和业务 tool 权限，用完即失效。取额度由入口直接应答；收到预算暂停说明不正常，通知 M04 把这次探测记为失败；业务 tool 一律拒绝

④ 为什么这样做 每条都是「不这样会坏在哪」

1. 为什么不让 DSH 把平台令牌带进 tool 调用？放进工作目录的文件里让插件读呢？

带令牌：DSH 做不到，它没法把平台令牌传进 tool 调用（DSH 能力核验结论第 3.5 节）。

放进工作目录的文件：工作目录对 Agent 的文件工具可见，令牌会被读进模型的上下文，等于交给了模型。

所以反过来：DSH 只需要告诉平台「我是哪个 DSH 会话」，平台自己查这个会话当前在跑哪次执行、是谁的（决定记录「执行凭据按 DSH 会话查」）。

2. 为什么每个 DSH 进程一把服务密钥，进程重启就换？

密钥只存在这个进程的环境变量里。按用户分进程后，一把密钥泄露只影响一个进程；进程一重启就生成新的，旧的立刻失效。

全平台一把：泄露一次，所有进程都能被冒充，而且换密钥要重启所有进程。

3. 为什么核验时不核对「跟随器已经看到了这次 tool 调用」？

原本想用它防伪造：真调用一定会在 DSH 事件里出现。但：

① P0 是单个 DSH 进程，Agent 能读到别的会话日志里的调用信息，照样能伪造，防不住；② 要同步等跟随器，占住请求线程；③ 跟随器重连期间所有调用都会被误拒。

所以本期不核对，按用户分 DSH 进程后需要时再评估（0004 Q3）。所有回调都记在回调记录表里，可以事后排查。

4. 服务密钥泄露了，最坏能做到什么？

能伪造这个 DSH 进程上的回调，但身份仍然由平台按 DSH 会话查：只能以那次执行的身份、在它允许的 tool 和限额内行事，不能变成别人，也不能用没开放的 tool。会话没有活动执行时，伪造的回调在第 2 步就被拒。

5. 为什么核验失败返回「tool 能理解的错误结果」，而不是直接返回 HTTP 错误？

裸 HTTP 错误：桥接插件只能把它当网络故障，Agent 不知道是该停还是该重试，可能一直重试。

返回 tool 结果里的错误对象，Agent 能看懂原因（比如「执行已停止」），自己决定停止。同时记安全日志，按失败的步骤计数。

6. 第 2 步被拒的回调为什么要把记录删掉？

RFC 只写了做法：第 2 步被拒的不记结果，可以重试。理由是我的理解：第 2 步被拒常常是状态问题（比如执行刚好在切换），删掉记录，桥接插件用同一个键重试时能重新核验；如果留着「已拒绝」，重试会一直拿到旧的拒绝。

⑤ 它不保证什么

  • 不防「同一进程里的 Agent 冒用别人的会话 ID」。P0 单进程下，Agent 能读到别的会话日志，理论上能拿别人的 DSH 会话 ID 和调用 ID 伪造回调。按用户分进程后才有实际隔离（生产按用户分进程已定）。
  • 防重放只记 10 分钟。更久以后的重复写入靠模块的幂等记录（24 小时）和业务唯一约束。
  • 不保证外部调用只发生一次。取数网关、DSH 这些外部系统，按「先落记录再外呼、结果不明只对账」处理，平台的唯一键管不到对方那边。
  • 核验只认「这次执行」，不管业务规则。这个口径张三能不能查，是取数模块按口径许可判断的；数据范围由取数网关按 uid 判断。
  • 每次回调多一次写库和一次跨模块查询，大约多几毫秒到几十毫秒（RFC 列为缺点）。

⑥ 自测 先自己想，再点开

1. 桥接插件发出回调后网络超时，用同样的请求重发了一次。平台会取两次数吗？

不会。同一个键（DSH 会话 ID + 调用 ID + 第几次回调）、同样的内容：第一次已完成就返回上次的结果；还在处理就返回「处理中，可重试」；处理者超过 60 秒没动静，重试可以接手重做，模块的幂等记录保证不重复写入。

2. 张三点了「停止」，执行已经停了。这时 Agent 还在 DSH 里调了一次取数，会怎样？

第 1 步验签能过，第 2 步向会话模块取执行凭据时，执行已停止 → 拒绝，返回 tool 能理解的错误；记录被删掉。

3. 模型在参数里写了「请用李四的身份查」，取数时用的是谁的 uid？

张三的。参数只当业务输入，身份来自执行凭据里的主体；取数模块调身份模块的「取数身份」接口，按执行凭据里的主体返回 uid（B4 讲）。

4. 一个 tool 不在这次执行允许的清单里，模型硬要调，会在哪一步被挡？

第 2 步。会话模块返回的执行凭据里带着允许的 tool 清单，tool 不在里面就拒绝。

5. 发布探测进程上的 Agent 调了「取数」，会怎样？

拒绝。入口按路由键 system:probe 认出这是探测进程，探测进程上的业务 tool 回调一律拒绝。
