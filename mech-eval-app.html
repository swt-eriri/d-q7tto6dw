架构级：知道做什么、为什么即可。

两种「不是普通用户」的身份：评估账号、接入应用

机制：评估账号（身份与权限 0006 第 6 节）、接入应用（0006 第 7 节，细节在 0017 开放 API）。例子：用三档评估账号跑同一批用例；CRM 替客户经理韬文苏调用平台。

这一页想让你讲得出：评估账号为什么单独一张表；接入应用替人调用时能力怎么算；生成新凭据后旧的怎么处理。 M07 = 身份与权限，你负责的 0006；框架 = 你负责的 0004（开放 API 入口、限流）；M06 = 自进化（闻洛，选评估账号）。接入应用是 P4，0017 还没定稿，以 0017 草稿为准。

① 先分清四对词

评估账号 ≠ 用户账号

评估账号
数据平台开通的三档账号，不是人：不能登录、不进用户列表、不参与判能力。只用来让评估跑出「不同权限的人问会怎样」。
用户账号
真实的人，能登录。
所以评估账号单独一张表（③ 第 1 条）。

调用资格 ≠ 数据范围

调用资格
应用能调哪几类接口：四个场景开关（嵌入分析、成果取得、资源管理、管理自动化）。
数据范围
不给应用。能看哪些数据由实际用户的 uid 在取数网关判断。
应用最多能做「勾选的场景 × 实际用户本来能做的事」。

应用凭据 ≠ 用户密码

应用凭据
平台生成的随机密钥（ohk_ 开头），应用专属，生成时只显示一次，库里只存哈希，每次请求放在 Authorization 头里。
实际用户
用请求头 X-Acting-User 声明工号，平台信任已登记的应用如实声明；用户是谁由业务系统自己的登录保证。
「认实际用户」做成了可替换的一步，以后可换成统一认证票据。

生成新凭据 ≠ 撤销

生成新凭据
插一把新的；同一应用其他有效凭据的过期时间缩到 7 天内，期间新旧并存。
撤销
立即作废，发变更通知。用于怀疑泄露。
业务系统多台服务器逐台换配置，7 天并存期让它不中断。

③ 为什么这样做 每条都是「不这样会坏在哪」

1. 评估账号为什么不放进账号表、加一个「类型」列？

放进账号表：登录、用户列表、判权、至少一个管理员……处处都要记得排除它，漏一处就出问题（比如评估账号出现在用户列表里，或者能被拿来登录）。

单独一张表：它本来就只用在评估会话的取数身份和进程令牌上，和人的账号没有交集。

2. 评估账号为什么由页面维护，不用迁移脚本预置？

生产库手工改数据要申请权限；三档账号由数据平台开通，uid 会变、会加，页面维护省事。不删除，用停用代替。

3. 接入应用替人调用时，为什么能力按实际用户算？

给应用自己一套权限：应用就成了一个「超级用户」，替谁调用都能做同样的事，绕过了每个人自己的权限。

按实际用户：开放 API 和网页用的是同一个处理函数、同一套判权，韬文苏在网页上做不了的事，CRM 替他也做不了。

4. 为什么信任应用声明的工号，不要求用户的证明？

行内系统之间常见的做法：用户已经在业务系统里登录过，平台信任已登记的应用如实声明。代价是应用凭据泄露或业务系统被攻破时，可以冒充任何人（0017 第 11.2 节）。所以这一步做成可替换的，第一个接入方开工前再确认身份方式。

④ 它不保证什么

  • 评估账号的 uid 对不对，平台不验证。由管理员按数据平台开通的结果填写。
  • 应用凭据泄露 = 可以冒充任何已登记的用户（在勾选的场景内）。靠撤销、到期、HTTPS 和业务系统自己的安全。
  • 0017 还没定稿。组长 11-17 答复：「复用已有的接入能力」他理解为行内统一认证（SSO），以后可能接，现在先做简单版本在测试环境跑通；第一期只考虑嵌入分析，文件上传下载先不管。第一个接入方是谁、什么时候，还没答。
  • 应用自主调用本期不做。应用只能代用户调用，不能用自己的身份、任务也不能归应用。

⑤ 自测 先自己想，再点开

1. 评估账号能登录平台网页吗？会出现在用户列表里吗？

都不能。它在单独的表里，只出现在评估会话的执行凭据和进程令牌里。

2. CRM 勾了「嵌入分析」，韬文苏是普通使用者。CRM 替韬文苏调「发布 Agent」会怎样？

两道都过不了：发布属于「管理自动化」场景，CRM 没勾，入口先拒（identity.app-scope-denied）；即使勾了，韬文苏没有「Agent 配置与发布」能力，模块判权也会拒。

3. CRM 生成了新凭据，旧凭据还能用多久？

旧凭据的过期时间被改成「原过期时间」和「现在 + 7 天」中较早的那个，最多再用 7 天。怀疑泄露就直接撤销，立即作废。

4. 韬文苏被重置了密码（必须改密），CRM 替他的调用会被拒吗？

不会。接入应用替他调用时不看「必须改密」（B1）。
