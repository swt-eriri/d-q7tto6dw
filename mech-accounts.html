账号管理里的并发和规则：两个人同时改，结果还对吗

机制：账号（身份与权限 0006 第 2.1 节）。例子：两个管理员同时把对方降级；两个管理员同时编辑同一个账号；两个进程同时启动都要建初始管理员；李四被移除后，同一个工号再建。

这一页想让你讲得出：为什么要锁住所有管理员行，而不是查一下数量；同时编辑怎么发现冲突；初始管理员靠什么只建一个；用户 ID 和工号为什么分开；移除和停用有什么不同。 M07 = 身份与权限，你负责的 0006。

① 先分清四对词② 走一遍③ 为什么这样做④ 它不保证什么⑤ 自测

① 先分清四对词

用户 ID ≠ 工号

用户 ID
平台内部的永久编号（usr_ 开头），全平台各表按它记归属，永远不变。
工号
登录时输入，可以更正。写入前去空格、转大写，在未移除的账号中唯一。
需求：修改姓名或更正工号，不改变对话、文件和 memory 的归属。

停用 ≠ 移除

停用
不能登录、不能操作，可以再启用，所有数据原样保留。
移除
标记删除：不再出现在列表、不能再用。同一事务清空网关 uid（审计记原值）、删除密码、作废会话和令牌。对话、文件仍归它。同一工号可以再建新账号。
移除后再建的同工号账号是另一个用户 ID，看不到旧账号的东西。

锁行 ≠ 乐观锁

锁行（悲观）
先 SELECT … FOR UPDATE 锁住，别人要等。用在「至少保留一个管理员」这种跨多行的规则上。
乐观锁
不锁，带着读到的版本号去改：WHERE id = ? AND 版本 = 3，改到 0 行说明别人先改了。用在「同时编辑同一个账号」上。
规则跨多行用锁行；只改一行、冲突少用乐观锁。

唯一约束 ≠ 先查再插

先查再插
查「工号有没有人用」，没有再插。两个请求同时查，都说没有，都插进去。
唯一约束
让数据库保证：第二个插入直接报错，捕获冲突即可。
工号唯一、uid 唯一、初始管理员只建一个，都靠唯一约束。
用到的一个基础概念：读已提交下为什么「只查数量」会被插队

行内数据库的隔离级别是「读已提交」：一个事务只能看到别人已经提交的数据。两个事务同时开始，各自查「启用的管理员有几个」，都看到 2 个（对方的修改还没提交），都认为「降掉一个还剩 1 个」，都提交了，结果是 0 个。锁住这些行，第二个事务就必须等第一个提交，再看到最新的结果。

③ 为什么这样做 每条都是「不这样会坏在哪」

1. 为什么要锁住所有启用的管理员行，而不是查一下数量？（第 1–3 步）

只查数量：两个管理员同时互相降级，两个事务都查到「有 2 个管理员」，都放行，最后一个管理员都不剩，平台没人能管理了（看第 3 步的按钮）。

锁住所有启用的管理员行：第二个事务要等第一个提交，再看到「只剩 1 个了」，拒绝（identity.last-admin）。停用、移除、降级管理员时都这样做。

2. 同时编辑同一个账号，为什么用版本号，不用锁？（第 4 步）

编辑页从打开到保存可能隔好几分钟，不能一直锁着。带版本号去改，后保存的那个改到 0 行，返回 common.conflict，前端提示「已被别人修改，请刷新」。

什么都不做：后保存的覆盖先保存的，先保存的人的修改悄悄丢了。

3. 两个进程同时启动都去建初始管理员，为什么不会建出两个？（第 5 步）

部署配置里给了初始管理员的工号和初始密码。两个进程都发现「没有启用的管理员」，都去插这个工号的账号，工号唯一约束挡住第二个，捕获冲突即可。

4. 为什么工号不能直接当用户 ID？

工号可以更正。更正一次，就要改全平台所有记归属的表（对话、文件、memory……）。

用户 ID 永久不变，工号只是账号上的一列。

5. 移除时为什么要清空 uid、删除密码？（第 6 步）

移除后同一工号可以再建新账号，新账号的 uid 默认也是这个工号。如果旧账号还占着 uid，新账号就建不了（uid 全表唯一）；清空 uid 并在审计里记下原值，既能再建，又能追溯。密码删掉，旧账号就彻底不能登录了。

④ 它不保证什么

  • 唯一的管理员忘了密码，就没人能重置。部署要求至少建两个管理员。
  • 锁行有代价。停用、降级管理员时会锁住所有启用的管理员行，期间其他改管理员的操作要等；管理员很少，这个代价可以忽略。
  • 乐观锁只能发现冲突，不能合并。后保存的人要刷新后重新改。
  • 姓名可以重复。只有工号（未移除的）和 uid 唯一。

⑤ 自测 先自己想，再点开

1. 平台只有两个管理员，A 正在停用 B，同时 B 正在降级 A。最后会怎样？

先锁到管理员行的那个事务先做完；后一个事务等它提交后，看到只剩一个启用的管理员，自己的操作会让管理员变成 0 个 → 拒绝（identity.last-admin）。最后一定至少剩一个。

2. 李四被移除后，新同事也叫李四、工号也是 A1024，能建吗？能看到旧李四的对话吗？

能建：工号只在未移除的账号中唯一。看不到：新账号是新的用户 ID，旧对话仍归旧的用户 ID。

3. 两个管理员同时给同一个工号建账号，会怎样？

工号唯一约束挡住第二个，返回工号重复的错误。不是先查再插，所以不会建出两个。

4. 为什么「至少一个管理员」用锁行，「同时编辑」用版本号？

前者是跨多行的规则（要看所有管理员），只能锁住这些行再判断；后者只改一行，从打开到保存时间长、冲突少，用版本号发现冲突就够了。
