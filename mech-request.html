一个请求进来经过什么：谁确认「你是谁」，谁判断「你能不能做」

机制：请求管道（后端框架 0004 第 3.1、4.1、4.2、4.5 节；身份与权限 0006 第 2.3、3.1 节）。例子：张三在页面上点「发送」。

这一页想让你讲得出：请求在入口经过哪几关、每一关挡什么；为什么入口只认证不授权；调用上下文里的主体从哪来；出错时返回什么。 框架 = 你负责的 0004；M07 = 身份与权限，也是你负责的 0006；M01 = 会话（嘉敏）。

① 先分清四对词

认证 ≠ 授权

认证
确认「你是谁」。入口（框架）做：从 cookie 查出是张三。
授权
判断「你能不能做这件事」。模块做：张三有没有对话能力、这个会话是不是他的。
入口只认证、不授权（0004 第 4.1 节）。

凭证 ≠ 主体

凭证
拿来进门的东西：网页用登录 cookie，开放 API 用应用凭据，tool 回调用签名。
主体
进门后平台内部认的「这是谁」，比如 UserPrincipal(usr_张三)。判权一律针对主体，不针对凭证。
凭证各不相同，进门后都换成主体，后面的代码不用关心是从哪个门进来的。

认证缓存 30 秒 ≠ 判权也有 30 秒延迟

认证缓存
入口把「这个 cookie 是张三」在本进程记 30 秒，免得每个请求都查库。
判权
模块调的判权接口每次都按主键查一次账号，不缓存，角色一变立刻生效。
所以张三被降级后，即使认证缓存还没过期，要管理能力的操作也会被立刻拒绝。

入口的粗拦 ≠ 模块的检查

粗拦
契约里可以给路由声明粗要求（比如「仅管理员」），入口据此先挡一道。
模块检查
模块仍然要自己判权。粗拦只是第一道，不能代替。
「这个会话是不是张三的」这种规则，入口根本不知道，只能模块判断。
用到的三个基础概念（不熟就点开）

cookie：浏览器替网站保存的一小段数据，每次访问这个网站自动带上。登录 cookie 的值是一个 32 字节的随机串；库里只存它的 SHA-256 摘要，库泄露了也拿不到能用的 cookie。

跨站请求伪造：张三登录着平台，又打开了一个坏网站，坏网站让他的浏览器偷偷给平台发一个写请求。浏览器会自动带上平台的 cookie，平台以为是张三自己发的。

契约（OpenAPI 文件）：手写的接口说明，规定每个接口收什么字段、返回什么。前后端都按它生成代码，入口按它校验请求。

③ 几类请求怎么进门 都走同一条管道，只是认证这一关不同

路径谁来调凭什么认人之后
/api/v1浏览器登录 cookie → 身份模块查出主体；写请求还要过防跨站检查本页走的就是这条
/open/v1行内业务系统（P4）应用凭据 + 声明的实际用户 → 身份模块；按应用限流每次调用发一条「应用调用」审计；具体做法在 0017
/internal/tool/v1DSH 里的桥接插件签名验证 + 向会话模块取这次执行的凭据A8 讲
/internal/exec/v1桥接插件（取剩余额度、登记预算暂停）签名验证 + 按 DSH 会话找活动执行A8 讲
/internal/eval/v1评估执行器服务凭据 + 核对它持有的任务租约主体是「自进化服务，带任务发起人」
/internal/stream/v1后台进程（推逐字输出）服务凭据A9 讲

/internal/* 和其他路径共用一个端口，反向代理不把它转发给办公网，外面的人连不到。

④ 为什么这样分 每条都是「不这样会坏在哪」

1. 为什么入口只认证、不授权？

让入口授权：入口就得知道每个模块的业务规则，比如「会话是不是他的」「这个 Agent 有没有对他开放」。规则散在入口和模块两处，改一处忘一处。

「你是谁」全平台只有一种算法，放在入口；「你能不能做」是业务规则，放在知道这些规则的模块里。入口按契约做的粗拦只是省一次无谓的处理。

2. 为什么主体不能由调用方自己填？（第 5 步）

让调用方填：任何人在请求里写一句「我是管理员」就成了管理员；Agent 也能在 tool 参数里写「替李四取数」。

主体只由入口按核验过的凭证构造：网页、开放 API 由身份模块解析，任务和事件由框架按任务记录、订阅声明构造。模块不能修改调用上下文，也不能凭空造一个。tool 回调的参数里不含任何身份字段。

3. 为什么认证要缓存 30 秒？停用了不就晚 30 秒生效吗？

不缓存：每个请求都要查一次会话表和账号表。缓存 30 秒能省掉大部分查询。

晚生效的问题这样处理：① 本进程收到账号变更通知（停用、改角色、作废会话……）时立刻清掉对应缓存，MVP 只有一个请求进程，所以是立刻生效；② 判权接口不缓存，要能力的操作立刻被拒；③ 只有多个请求进程时，其他进程的认证缓存最多晚 30 秒（B6 讲）。

4. 已经有 SameSite 了，为什么还要防跨站检查？（第 4 步）

只靠 SameSite=Lax：同一个主域名下的其他系统不算「跨站」，它们发的请求浏览器照样带 cookie。行内很多系统都在同一个主域名下。

cookie 双提交：入口下发一个页面脚本能读的 XSRF-TOKEN cookie，前端写请求时把它抄进请求头。别的站点读不到本站的 cookie，抄不出来。不用存库、不需要密钥，是 Spring Security 自带的。

5. 为什么没分类的错误只返回请求 ID？（第 8 步）

把异常原样返回：堆栈里有类名、SQL、内部地址，等于把系统内部结构告诉了外面。

返回 500 common.internal 和请求 ID，完整堆栈记在日志里。用户报错时给出请求 ID，按它就能在日志里找到这次请求（请求 ID、追踪 ID 每条日志都带）。

6. 为什么在入口按契约校验，契约外的字段也要拒？（第 6 步）

入口校验过，模块拿到的数据一定符合契约，不用每个模块各自检查格式。

契约外字段如果放过：前端传了一个后端其实不认识的字段，以为生效了，后端悄悄忽略，问题很久才被发现。直接拒绝，前后端不一致当场暴露。

⑤ 它不保证什么

  • 入口不授权，模块忘了判权就是漏洞。入口放进来的只是「确认是张三」，张三能不能做这件事，全靠模块调判权接口、检查对象归属。只能靠评审和测试。
  • 粗拦只挡得住契约里声明了的路由。没声明的，入口一律放给模块。
  • 多个请求进程时，认证缓存最多晚 30 秒。停用的人在其他进程上还能「通过认证」最多 30 秒；但要能力的操作会被判权拒绝。
  • 入口不管业务错误的含义。模块抛出带类型的错误（找不到、无权、冲突、校验失败、依赖不可用），入口只负责翻译成统一的 HTTP 状态和错误体。
  • 请求里调 DSH 有 10 秒超时。超时返回 503 common.dependency-unavailable，长时间的工作不能放在请求里做（A5、A6）。

⑥ 自测 先自己想，再点开

1. 张三把浏览器里的 cookie 复制给李四，李四能用吗？平台能分辨吗？

能用，入口只认 cookie，分辨不出是谁的浏览器。所以 cookie 设成 HttpOnly（页面脚本读不到）、Secure（只走 HTTPS），会话固定 12 小时；张三退出、改密，或被停用、重置密码时会话作废，这个 cookie 立刻失效。

2. 管理员 10:00:00 把张三降级成普通使用者。10:00:10 张三在同一个请求进程上打开「Agent 配置」并保存，会怎样？

降级时身份模块发出变更通知，本进程立刻清掉张三的认证缓存，重新认证得到新的能力清单。即使是在另一个请求进程上、认证缓存还没过期，保存时模块调判权接口（不缓存）也会被拒（403），并留下一条访问拒绝审计。

3. 某个模块的开发者忘了调判权接口，入口能拦住吗？

只有当契约里给这个路由声明了粗要求（比如「仅管理员」）时，入口才会先挡一道；否则拦不住。入口只认证不授权，所以验收时要专门测「无权限的人调这个接口」。

4. 请求处理时抛出了一个没人预料到的空指针异常，用户看到什么？你怎么查？

用户看到 500 common.internal 和一个请求 ID。拿请求 ID 去日志里搜，能找到完整堆栈和这次请求的上下文。

5. 张三的账号「必须改密」（刚被重置过）。他用旧 cookie 发消息会怎样？

重置密码时他的会话全部作废，旧 cookie 认证失败（401），要重新登录。登录后能力清单为空，前端只显示改密页；发消息时判权自然拒绝，不需要另写拦截。

出处：0004 第 3.1 节（调用上下文：字段、主体从哪来、模块不能修改）、第 4.1 节（请求管道、入口只认证不授权、路由粗要求、/internal/* 不对办公网转发）、第 4.2 节（cookie 会话、30 秒缓存与清缓存、cookie 双提交、请求体 1 MB）、第 4.5 节（错误映射）、第 6.4 节（DSH 普通调用 10 秒超时）；0006 第 2.2–2.3 节（能力、判权不缓存、必须改密）、第 3.1 节（登录流程第 5 步）、第 3.3 节、第 3.4 节、第 8.1 节（resolveWebSession、checkCapability 的签名和错误）。
示意，不是 RFC 定的：时间、ID、发送消息的路径、请求体内容。
待核实：防跨站检查不通过时具体返回的状态码，RFC 只写「被拒」（Spring Security 默认是 403）；契约校验失败的具体错误码见 RFC-0003 第 2.7 节，本页只写「400 一类」。
