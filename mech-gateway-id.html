取数用谁的身份：只用登记过的 uid，不猜

机制：取数身份（身份与权限 0006 第 4 节）。例子：Agent 替苏文韬取数；苏文韬的工号更正了；管理员清空了他的 uid；自进化和评估账号取数。

这一页想让你讲得出：取数网关认的身份从哪来；为什么 uid 为空时不拿工号顶替；为什么只能在 tool 回调里查；自进化为什么不能取数；uid 为什么全表唯一、改它为什么要审计。 M07 = 身份与权限，你负责的 0006；M03 = 取数（拿 uid 去调取数网关）。

① 先分清四对词

工号 ≠ 网关 uid

工号
登录时输入的，可以更正（需求 OH-IAM-F011）。
网关 uid
取数网关认识的身份，网关按它判数据范围。是账号表的一列，新建账号时默认填工号，管理员可以改。
一般就是工号（组长 11-16），但两者是两列：更正工号时 uid 不跟着变。

未映射 ≠ 不允许

未映射
这个人可以取数，但还没登记 uid。不能真实取数，提示「账号还没开通取数身份，请联系管理员」。
不允许
这个主体根本不该取数：服务主体，或账号已停用、移除。
还有第三种：已映射，返回 uid。

能力 ≠ 数据范围

能力
平台判断：能不能对话、能不能导出（B1）。
数据范围
能看哪些数据，由取数网关按 uid 判断。平台不维护部门授权，管理员角色也不扩大取数权限。
平台只负责「把对的人的 uid 交给网关」。

执行凭据里的主体 ≠ 模型填的参数

执行凭据
入口核验 tool 回调时从会话模块查来的（A8），取数身份就按它里面的主体查。
参数
模型填的，不含身份。模型写「用韬文苏的身份」也没用。
Agent 没法替别人要 uid。

② 走一遍

③ 四种主体各返回什么

主体返回
用户有 uid → 已映射（uid）；没有 → 未映射；已停用或移除 → 不允许
接入应用 + 实际用户按实际用户，同上
评估账号同上，按评估账号自己的 uid 和状态
服务不允许：自进化不继承管理员的数据权限，打分、探测不取数

只能在 tool 回调里调（前提：调用上下文里有可信执行上下文）。每次 tool 调用按主键查一次，不缓存。

④ 为什么这样做 每条都是「不这样会坏在哪」

1. uid 为空时，为什么不拿工号临时顶替？（第 4 步）

顶替：猜错了，就是用别人的数据权限取数。比如管理员清空 uid 正是因为发现它不对，结果平台又自己填回去了。

新建时默认填工号不一样：那是管理员看得见、改得了的登记；取数时临时顶替是没人看见的猜测。

2. 更正工号时，uid 为什么不跟着变？（第 2 步）

uid 一变就是数据权限变了。这种事不能悄悄发生，由管理员在编辑页决定改不改，改了要发审计。

3. uid 为什么全表唯一？

不唯一：同一个 uid 绑给了两个人，一个人就能用另一个人的数据权限取数。

4. 为什么只能在 tool 回调里查？

取数只发生在 Agent 调「取数」tool 时。要求调用上下文里有可信执行上下文（只有入口核验 tool 回调时能生成，A8），就保证了主体来自核验过的执行凭据，而不是哪个模块自己传进来的。

5. 王经理是管理员，他发起的自进化为什么不能用他的身份取数？

能的话：自进化跑起来会以管理员的数据权限取数，权限比任何一个真实用户问问题时都大，而且结果混进了自进化的评估里。

自进化要看「不同权限的人问会怎样」，用的是数据平台开通的三档评估账号（B7）。

⑤ 它不保证什么

  • 不保证 uid 是对的。平台只保证用登记的那个；登记错了由管理员发现和更正。
  • 不管数据范围。能看哪些数据全在取数网关。
  • 不管口径能不能用。那是取数模块按口径许可判断的业务规则。
  • 知识服务的身份本期不存。本期用本地知识文件；接入知识平台时，再加一个可空列和返回值里的一个字段（0006 Q5，等知识平台确定要什么身份）。
  • 取数网关最终版不归平台开发，以后可能变。uid 的来源（组长说一般是工号）随之可能变（组长 11-16）。

⑥ 自测 先自己想，再点开

1. 新建账号时只填了工号、姓名、角色，他能取数吗？

能（如果网关认这个 uid）。新建时 uid 默认填规范化后的工号。

2. 管理员把苏文韬的工号从 309091 更正为 309019，Agent 再替他取数用哪个 uid？

还是 309091。更正工号不改 uid，要不要改 uid 由管理员在编辑页另外决定。

3. 管理员想把韬文苏的 uid 也设成 309091，会怎样？

被拒：uid 全表唯一，同一个 uid 不能绑给两个主体。

4. CRM 替韬文苏调用时取数，用谁的 uid？

韬文苏的。接入应用的主体按实际用户取 uid；应用只被授予调用资格，不被赋予数据范围。

出处：0006 第 1.1 节（几个标识）、第 2.1 节（移除时清空 uid）、第 4 节（取数身份全部规则）、第 6 节（评估账号）、第 7 节（接入应用按实际用户）、第 8.1 节（GatewayIdentityQuery、Mapped / Unmapped / NotAllowed）、第 10.1 节、第 13 节 Q2、Q5。
示意，不是 RFC 定的：时间、工号、uid 的具体值、评估账号的 uid。
